# macos-actions-runner-kit

[English](README.md) · [Подключение workflow](docs/INTEGRATION.md) · [Границы безопасности](SECURITY.md)

Включай свой Mac для GitHub Actions **только когда нужна сборка**.
Задания выполняются под отдельным обычным пользователем, логи остаются в GitHub.
Остановка — **Ctrl+C**. Без фоновой службы и автоматического запуска сборок.

> [!IMPORTANT]
> Только доверенные приватные репозитории. Отдельный пользователь — **не виртуальная машина**.
> Не запускай публичные и непроверенные PR на личном Mac.

> [!NOTE]
> Ранний open-source проект под [MIT](LICENSE). Проверка установки на втором Mac отложена;
> Intel и полный подписанный релиз для отдельного комплекта пока не проверены.
> [Что проверено](docs/VERIFICATION.md) · [Что осталось](docs/RELEASE-CHECKLIST.md).

## 1. Скачай и открой папку

На странице этого репозитория: **Code → Download ZIP**, затем распакуй архив.
Открой Terminal под своим обычным аккаунтом администратора:

```bash
cd "$HOME/Downloads/macos-actions-runner-kit-main"
ls runner tool/runner/config.example.json
```

Распаковал в другое место — укажи его настоящий путь. При ошибке остановись.

## 2. Укажи свой приватный репозиторий

Замени `OWNER/REPO` на проект, **который будешь собирать**, не на публичный репозиторий помощника:

```bash
bash runner configure --repository OWNER/REPO --lang ru
```

Создастся локальный `tool/runner/config.json`, исключённый из Git. Секреты туда не нужны.
Только Android: добавь `--platforms android`; только iOS: `--platforms ios`.

## 3. Подготовь Mac

```bash
bash runner setup --lang ru
```

В запросе sudo введи пароль своего Mac. Если создаётся пользователь `ci`, задай ему
отдельный пароль. Скрипт подготовит аккаунт, отдельную копию Android SDK и команду `ci-runner`.

> [!NOTE]
> Нужен разработческий Mac: Python 3.12+, Ruby 3.3, `git`, `curl`, `jq`, `gh`;
> Xcode 26.3 для iOS; полный Android SDK и JDK для Android.
> Место — под копию SDK **и ещё 20 GiB**. Недостающие компоненты покажет установщик.
> Xcode, принятие лицензии Apple и установку недостающих инструментов выполняет владелец Mac.

## 4. Подключи — один раз

```bash
sudo -iu ci
```

**Дождись приглашения `ci@…`**, затем отдельно выполни:

```bash
ci-runner register
```

Открой показанную страницу GitHub. Скопируй **только токен после `--token`**
и вставь в скрытый запрос терминала — не в команду, чат или файл.
Нет доступа к настройкам runner — попроси токен у администратора репозитория.
Менять рабочий стол macOS и входить в личный Apple ID не нужно.

## 5. Запускай по необходимости

Под `ci` (в новом терминале сначала `sudo -iu ci`):

```bash
ci-runner start
```

Дождись **Listening for Jobs**. В подготовленном workflow GitHub нажми **Run workflow**,
выбери `runner=self-hosted`. [Workflow один раз подключает владелец проекта](docs/INTEGRATION.md).
Не закрывай терминал/крышку, держи Mac на питании.
После завершения **всех заданий** нажми **Ctrl+C**. Команда `exit` вернёт в свой аккаунт.

> [!TIP]
> Проверка: `ci-runner doctor`. Английский: `ci-runner --lang en doctor`.
> Обновление: останови runner и повтори setup из проверенных новых исходников.
> [Подробности и устранение ошибок](tool/runner/OPERATIONS.md).

Комплект устанавливает runner, **но не настраивает универсальную подпись и доставку Flutter**.
Команды проекта, секреты и их очистка остаются ответственностью владельца workflow.
